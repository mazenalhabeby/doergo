⑦Which four survive
WHICH FOUR SURVIVE
Eight candidates, four slots. §3.27 says “up to four” and stops there — this is the missing half.
1Drop every tile the viewer cannot use.Each carries its own gate. This is usually most of them.
2Badged tiles first, by badge age.Something is waiting. A doorway with a number on it beats an empty verb every time.
3Then the create actions, in registry order.Stable — a toolbar that reorders itself is a toolbar you cannot learn.
4Cut to four. Fewer than two, hide the card.One tile is a button pretending to be a widget.
⚠️ Step 2 is the only one that moves. Badges come and go through the day, so the last two slots are stable and the first two are live — which is the right way round for muscle memory: the thing you reach for without looking never moves.

⑫The table already exists
⚠️ HALF OF THEM ALREADY HAVE A REGISTRY
// src/lib/manage-rows.ts { icon, labelKey, descKey, route, color, permission, orgWide, module? }
MANAGE_ROWS is exactly the table a tile rail needs — icon, label, route, permission, scope, module — and manageRowsFor(user) already filters it. Its own comment states the rule:
“The tab and the list read the same array, so a member never opens a Manage tab to find nothing in it, and never sees a row that would refuse them.”
The rail must read that array too. A second gated list of the same destinations is §2.4 rule 1 happening again — “asked separately they drift” — and the file already records what drift cost: crmViewOwn alone as a gate, and a member seeing Clients on the web and not on the phone.
So the change is one table, three surfaces: extend the same shape to the member’s own screens, add two fields, and let the Manage tab, the More sheet and this rail all read it.

§3.26The one that stopped being hard. Its own entry calls it “the only widget needing per-instance configuration, which is why it is last” — a saved report id in the layout row, a picker, a per-member setting. As a TILE it needs none of that: it opens the reports screen and the screen remembers.
§3.18⚠️ It cannot show a balance. TimeOffRequest has no allowance and no remaining days — grepping for balance, allowance or remainingDays returns nothing. The badge is days BOOKED AHEAD, which is computable.
§3.24⚠️ Never a “send”. “A draft’s PDF is watermarked; only ISSUED produces a clean document.” The tile opens the list, and the list knows which are drafts.
⚠️ And §3.20 overtime is NOT one of these. getActive() returns one live request; it is a conversation on a running shift with the member answering in the middle. Somebody asked to stay ninety minutes cannot be left to notice a badge. It folds into the shift clock as a state.
