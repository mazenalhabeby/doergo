Request types the office designs itself

Today a member can ask for leave, a remote day, different hours or overtime — and everything else goes into "Other" as free text, with no fields, no fixed approver and nothing to report on. This lets each organization add its own request types: a name, the fields to fill, who may send it and who approves it.

Choices in this design

  • Types belong to the organization; each can be limited to some workspaces or roles. The four built-in kinds stay and keep their special effects (leave counts against the allowance, a remote day allows away clock-in, and so on). A custom type never changes hours or pay on its own.
  • Field kinds: short text, long text, number, money (in the workspace's currency), date, date range, time, choice from a list, yes/no, photo or file. Each can be required.
  • Up to three approval steps, in order. Nobody approves their own request. The approver set is resolved when it reaches the step, so a new leader takes over open requests.
  • Changing a type's fields later never changes requests already sent: each request keeps the form it was sent with.
  • Offline: a member can fill and send it without signal; it goes when the phone reconnects, like leave today.
  • Which Option or module carries it, and its price, is a separate decision.
