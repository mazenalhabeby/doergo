Your question · researched 18 Oct 2026

Replace the web with a desktop app?

The phone works offline because it is an app. Should the web move to a desktop app, so everything works offline on desktop and phone, and we stop using the web? Is desktop faster than web?

Short answer

Keep the web. Make it work offline where it helps.

Not recommended

Dropping the web for a desktop app

Not faster, costs more, and loses clients, sign links and the operator console.

Recommended

Web first, offline where useful

Installable web app, local copy + queued writes like the phone, and a thin desktop wrapper only if customers ask.

Speed

A desktop app runs the same web engine

Electron ships a whole Chrome; Tauri uses the system’s browser engine. The screens render the same way — what makes an app fast is its data and requests, which the last audit already tuned.

Electron app
200–300 MB
Tauri app
30–40 MB
Browser tab
shared

Idle memory, published comparisons (indicative; one 2026 benchmark reports 168 MB Electron vs 42 MB Tauri). A browser tab shares the browser that is already open.

Offline

The web can work offline too

Linear works offline inside the browser: a local copy of the data, edits saved locally first and sent when the connection returns — the same idea as our phone’s offline engine.

Office PCs · Chrome / Edge

Works well

Local database in the browser (IndexedDB), installable app window, storage that is not cleared while the app is used.

iPhone Safari

The hard limits are here

No background sync, storage can be cleared after days of not opening. Our field workers use the native app, so this does not touch them.

Who needs offline

The field, not the office

Offline matters

Workers in the field

  • Clock in and out, rests
  • Job steps, photos, signatures
  • Already covered by the phone app
Needs live data

Managers and dispatchers

  • Live map, who is on site now
  • Approvals, chat, the team’s state
  • Meaningless without the internet

Field-service leaders follow this pattern: offline-first mobile app + web for the office (Salesforce Field Service, FieldPulse, FieldAware, Fieldbase).

What dropping the web costs

Things that must open in a browser

Must stay web

  • Client portal
  • Signing links sent to customers
  • Operator console
  • Office staff on shared or locked-down PCs
Desktop overhead

Running a desktop app

  • Code signing: Apple $99/year, Windows certificate ~$200–700/year
  • First signing + update pipeline: ~2–3 weeks
  • Every update goes through installation; the web updates for everyone at once
What the leaders do

Desktop is an addition, never a replacement

Linear, Slack and Notion kept their websites. Their desktop apps are a thin wrapper around the same web code.

Our recommendation

Three steps — the best of both

Step 1

Installable web app

Opens from the desktop with its own icon and window — no store, no signing cost.

Step 2

Offline where it helps

Read recent jobs, rota and timesheets offline; keep safe edits until the connection returns — the phone engine’s idea.

Only if customers ask

Thin desktop wrapper

Tauri around the same web app, for tray, start-up and system notifications.
