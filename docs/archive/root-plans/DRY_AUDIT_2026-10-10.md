## 1. 🔴 Security guards exist twice

| Gateway copy (what actually runs) | Shared copy (exported, used by nothing) | Differences |
|---|---|---|
| `gateway/src/common/guards/onboarding-complete.guard.ts` | `shared/src/guards/onboarding.guard.ts` | import lines only |
| `gateway/src/common/guards/customer-confinement.guard.ts` | `shared/src/guards/customer-confinement.guard.ts` | import lines only |
| `gateway/src/common/guards/customer-scope.guard.ts` | `shared/src/guards/customer-scope.guard.ts` | import lines only |

- `gateway/app.module.ts` (APP_GUARD) and the portal module import the **gateway** copies.
- The `shared` copies are exported from `shared/src/guards/index.ts` but nothing imports them.
- The two copies of each guard are identical today. But a fix made to the `shared` version
  would look correct, pass review, and never run.

**Fix:** delete the three gateway files and import the classes from `@hbcfield/shared`.
Do it the other way round (delete the `shared` copies) only if those guards must stay
gateway-private. Either way, keep one copy.

## 2. 🟠 Date keys: 42 hand-written `toISOString().slice(0, 10)`

There is no shared "date → `YYYY-MM-DD`" helper, so every service writes its own. Local
one-line helpers doing the same thing:

- `task-service/technicians/technicians.service.ts:33` and `:662`
- `task-service/technicians/cover.service.ts:46` and `:85`
- `auth-service/documents/document-common.ts:437`
- `auth-service/invoices/invoice.service.ts:1394`

**About 16 sites are correct as written.** They read `@db.Date` columns, where UTC midnight
is the date: leave start/end, holiday `date`, `expiresOn`, `effectiveFrom`.

**About 10 sites compute a day from a timestamp, or "today", in UTC.** Between 00:00 and
02:00 Vienna time they produce yesterday. This is the bug class that was fixed once
already ("today a day early after midnight in Austria"):

- `technicians.service.ts:340`, `:350`: the performance chart buckets **completed jobs and
  hours worked** by UTC day. A shift clocked in at 00:30 counts on the previous day.
- `invoice.service.ts:49`, `:81`, `:266`: the default exchange-rate day and the **default
  invoice issue date**. These only apply when the request sends no date; the web form
  normally does.
- `technicians.service.ts:1356`: availability "today". UTC on purpose, and commented as such.
- `exchange-rate.service.ts:57`, `customers.service.ts:1080`, `analytics.service.ts:69-70`:
  review each one.

**Fix:**
- Add two shared helpers: `dateKeyUTC(d)` for `@db.Date` values, and `localDateKey(d, zone)`
  built on the existing `localPartsIn`.
- Replace the 42 sites, choosing the right helper for each.
- Fix the performance-chart bucketing to use the workspace zone.
